# Блок «Полезное сегодня»

## Назначение

Блок на странице `/today` даёт пользователю четыре коротких типа пользы:

1. что ожидается по циклу;
2. что фактически повторялось в недавних отметках;
3. есть ли ситуация, которую важно проверить;
4. где открыть образовательные материалы.

Карточки имеют компактный вид и содержат один основной текст. Вся поверхность карточки кликабельна.

## 1. Прогноз месячных

Карточка отвечает на вопрос: «Что ожидается дальше?» и отображается всегда.

Возможные состояния:

- `Месячные: 16–22 августа` — прогнозируемый диапазон;
- `Месячные: 1-й день` — месячные отмечены сегодня;
- `Месячные пока не начались` — прогнозный диапазон закончился;
- `Прогноз месячных` — для расчёта пока недостаточно данных.

Переходы:

- при наличии прогноза карточка открывает `/calendar`;
- при отсутствии данных карточка открывает `/calendar?action=period`.

Прогноз всегда показывается диапазоном. Он является календарной оценкой, не подтверждает овуляцию или беременность и не подходит как метод контрацепции.

## 2. Наблюдение недели

Карточка отвечает на вопрос: «Что пользователь часто отмечал в последние семь дней?»

Примеры:

- `Усталость — 3 раза`;
- `Спазмы — 2 раза`;
- `Мало энергии — 3 раза`;
- `5 отметок о состоянии`.

Правила показа:

- учитываются только фактические ежедневные записи за последние семь дней;
- необходимо минимум три записи;
- если записей меньше трёх, карточка полностью скрыта;
- карточка не объясняет причину симптома и не формулирует медицинский вывод.

По нажатию открывается `/insights`, где можно увидеть основание наблюдения и связанные записи.

## 3. «Важно проверить!»

Это контекстная safety-карточка. Она не отображается постоянно и появляется только при наличии основания:

- боль 7/10 или выше;
- обильные месячные;
- месячные не начались после окончания прогнозного диапазона.

Переход зависит от причины:

- сильная боль → `/concerns/pain`;
- обильные месячные → `/concerns/heavy-flow`;
- задержка → `/concerns/delay`.

Сценарий после открытия показывает отмеченные факты, безопасный следующий шаг и признаки, при которых нужна плановая или срочная помощь. Mira не ставит диагноз и не назначает лечение.

Если основания отсутствуют, карточка полностью скрыта. Нельзя показывать пользователю ложное предупреждение только для заполнения интерфейса.

## 4. «Для прочтения»

Постоянная минимальная карточка, которая открывает `/knowledge`.

Раздел содержит образовательные материалы о:

- цикле и его фазах;
- месячных;
- боли и безопасной самопомощи;
- выделениях;
- ПМС;
- признаках, требующих внимания.

Карточка не содержит персонального вывода и не использует медицинские ответы пользователя для выбора рекламного или внешнего контента.

## Порядок карточек

Карточки располагаются в следующем порядке:

1. прогноз;
2. наблюдение недели, если доступно;
3. «Важно проверить!», если есть основание;
4. «Для прочтения».

В production возможны следующие наборы:

- прогноз + чтение;
- прогноз + наблюдение + чтение;
- прогноз + важная проверка + чтение;
- все четыре карточки.

## Источники данных

- прогноз: даты начала и окончания месячных, длина и регулярность цикла;
- наблюдение: настроение, энергия, боль, симптомы и другие ежедневные отметки;
- важная проверка: текущая боль, интенсивность месячных и положение текущей даты относительно прогнозного диапазона;
- чтение: статическая библиотека материалов.

Постоянным источником пользовательских данных является Supabase PostgreSQL. Блок не записывает медицинские данные в `localStorage`, URL или продуктовую аналитику.

## Локальный preview-режим

В текущей feature-ветке при `NODE_ENV=development` принудительно отображаются все четыре карточки для визуального тестирования. Для недостающих наблюдения и важной проверки используются только UI-примеры:

- `Усталость — 3 раза`;
- `Важно проверить!`.

Preview-режим не создаёт записи в базе данных. В production-сборке используются только реальные условия показа.

## Реализация и тесты

Основные файлы:

- `apps/web/app/today/page.tsx` — отображение и development-preview;
- `apps/web/lib/domain/today-cards.ts` — чистая логика выбора карточек;
- `apps/web/lib/domain/today-cards.test.ts` — unit-тесты состояний;
- `apps/web/app/globals.css` — размеры и визуальные состояния.

Ключевые проверки:

- наблюдение скрыто при менее чем трёх отметках;
- диапазон прогноза форматируется корректно;
- сильная боль открывает safety-сценарий;
- важная карточка отсутствует без основания;
- карточка чтения открывает библиотеку знаний.
