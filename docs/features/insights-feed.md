# Insights 9.6

## Назначение

`/insights` — сфокусированная персональная выжимка из фактических записей пользователя. Экран отвечает на четыре вопроса: что Mira заметила, на каких данных, насколько устойчиво повторение и что можно сделать дальше.

Подробная аналитика остаётся в `/analytics` и `/insights/symptoms/[name]`. Образовательные материалы находятся только в `/knowledge`.

## Структура

### Для вас

- один главный инсайт с одним основным действием;
- спокойный статус уверенности: `first_signs`, `moderate`, `strong` или фактическое изменение;
- диапазон дней цикла и размер выборки;
- сворачиваемое объяснение «Почему Mira это показывает»;
- компактный список вторичных наблюдений;
- сворачиваемая прозрачность данных.

### Проверить

- короткие маршруты по боли, обильному кровотечению и задержке;
- переход к отчёту для врача;
- явное пояснение, что результат не является диагнозом.

## Правила данных

- заметное изменение приоритетнее повторяющегося симптома;
- при недостаточной выборке вывод не показывается;
- отсутствие записи не считается нулём или отсутствием симптома;
- ключ инсайта версионируется по доказательствам: изменились факты — появился новый ключ;
- `readAt` и `dismissedAt` сохраняются в PostgreSQL для авторизованного пользователя;
- в demo-режиме взаимодействия живут только в памяти процесса, без browser storage;
- интимные данные не анализируются без отдельного согласия.

## Состояния

- loading;
- недостаточно данных;
- нет новых наблюдений;
- ошибка загрузки с повтором;
- неблокирующая ошибка синхронизации взаимодействий;
- optimistic dismiss с временным действием «Вернуть».

## События продукта

- `insights_viewed`;
- `insight_detail_opened`;
- `insight_evidence_opened`;
- `insight_dismissed`;
- `insight_restored`;
- `insight_check_started`.

События содержат только имя и route. Названия симптомов и медицинское содержимое в них не передаются.

## Целевые метрики

- 60% открытий главного инсайта;
- 25% переходов в подробности;
- 15% последующих записей в дневник;
- менее 8% быстрых выходов.
