# P0: упрощение data-layer

**Статус:** implemented
**Приоритет:** P0
**Владелец решения:** Mira

## Цель

Упростить добавление новых полей и функций без изменения пользовательского интерфейса: разделить клиентские операции по областям, убрать дублирование контрактов и не загружать историю здоровья вместе с базовым профилем без необходимости.

## Первая версия

- Входит: общие Zod-контракты profile/entry, отдельные client API, demo-fixture, разделение `/api/users` и `/api/entries`, совместимый фасад `demo-session.ts`.
- Не входит: редизайн, новый store, изменение Prisma schema, пагинация аналитики и миграция всех экранов на прямые импорты новых модулей.

## Данные

- `/api/users` читает и сохраняет только профиль и настройки.
- `/api/entries` возвращает авторизованную историю с опциональным диапазоном `from`/`to`.
- Экраны сохраняют прежнее поведение через совместимый клиентский фасад.
- PostgreSQL остаётся единственным постоянным источником данных здоровья.

## Безопасность и приватность

Оба endpoint используют текущую серверную аутентификацию. Диапазон дат валидируется, а запись дневника больше не принимается endpoint профиля.
