# Mira: правила работы для Codex

- Основная локальная копия: `/Users/iskander/Documents/мира`.

- Перед любой работой прочитать [`docs/PROJECT_MAP.md`](docs/PROJECT_MAP.md), затем только документы, относящиеся к задаче.

## Как начинать задачу

1. Проверить `pwd`, `git remote -v`, активную ветку и `git status --short`.
2. Начинать новую работу от свежей `main` в отдельной `feature/*`, `fix/*` или `docs/*` ветке.
3. Найти активный route в `apps/web/app`, затем прочитать только его компоненты, API и domain-модули.
4. Не менять и не удалять чужие незакоммиченные файлы.
5. Перед правкой сформулировать затронутый пользовательский поток и минимальный набор файлов.

## Архитектурные границы

- Frontend: Next.js App Router, React 19, TypeScript, CSS в `apps/web/app/globals.css`.
- Авторизация: Supabase Auth; серверная сессия поддерживается cookie через `@supabase/ssr`.
- Данные здоровья: PostgreSQL через серверные API и Prisma. Не обращаться к таблицам здоровья напрямую из браузера.
- Расчёты цикла и продуктовая логика: чистые модули в `apps/web/lib/domain`; добавлять или обновлять тесты при изменении расчётов.
- PWA: регистрация в `PwaRegister`; сессия восстанавливается через `AuthSessionRestorer`.
- Не добавлять новый store, persistence-слой или зависимость без необходимости.

## Продуктовые правила

- Mira помогает понимать себя, но не ставит диагнозов и не обещает медицинскую точность.
- Не превращать отсутствие данных в ноль или подтверждённый вывод.
- Today — ориентация и быстрые действия; подробная история находится в Calendar/Analytics.
- Чувствительные данные собирать и показывать только с ясной целью.
- Интерфейс и тексты проверять mobile-first на русском языке.

## Проверка и релиз

После изменения запускать подходящий минимум:

```bash
npm run lint
npm test
npm run build
git diff --check
```

Для production:

1. Миграции Prisma применяются отдельно через `npm run db:deploy`.
2. Изменения проходят через PR в `main`.
3. Production публикуется Vercel только из `main`.
4. Проверить GitHub Actions, статус Vercel и основные маршруты на production-домене.
5. Не коммитить `.env*`, ключи Supabase или другие секреты.
